# Мониторинг CPU

`npm run dev` запускает страницу с явно обозначенным демонстрационным потоком:
43 201 точка за сутки, новое измерение каждые 2 секунды.

Для подключения сервера передайте в `CpuChart` реализацию `CpuSource` вместо
`demoCpuSource` в `src/App.tsx`. Метод `subscribe(onSamples, onError)` должен сначала
передать историю, затем пакеты новых измерений и вернуть функцию, закрывающую
соединение и отменяющую незавершённую загрузку. Источник должен иметь стабильную
ссылку; смена источника пересоздаёт подписку и очищает график.

Время — Unix timestamp в миллисекундах, CPU — число от 0 до 100 либо `null`
для пропуска. Данные поступают по возрастанию времени. Повтор последнего timestamp
заменяет значение; запоздавшие, будущие и некорректные точки отбрасываются.
Кольцевой буфер хранит последние сутки с пределом 100 000 точек; при превышении
предела удаляются самые старые. Для потока плотнее этого предела адаптер должен
агрегировать измерения до подачи в компонент.

Yagr рисует на Canvas. Поток обрабатывается вне React state, график получает
пакетные обновления с интервалом 250 мс через `requestAnimationFrame`. В скрытой
вкладке отрисовка приостанавливается, буфер остаётся ограниченным. Выбранный масштаб
сохраняется при поступлении данных. Цвета берутся из Gravity UI, тема следует
за текущим `ThemeProvider` (на странице используется системная тема).

Версия Yagr закреплена: в 5.3.1 полная замена серии и `setScales` для оси X
пересоздают uPlot. Компонент обновляет публичный `config.timeline` и серию по ID,
а диапазон меняет через публичный `uplot.setScale`. При обновлении зависимости
следует проверить это поведение снова.

Проверки: `npm run build` (TypeScript и production build), `npx vitest run`
(буфер, пакетирование, масштаб, смена темы, очистка ресурсов в StrictMode).
Тесты жизненного цикла используют замену Yagr и не измеряют реальную скорость Canvas.
Вручную следует проверить светлую/тёмную темы, ширину около 375 и 1400 px,
подсказки и масштабирование, состояния загрузки, отсутствия данных и ошибки.
