# Мониторинг CPU

Интерактивный график на `@gravity-ui/yagr` с историей за сутки. По умолчанию
используется демонстрационный поток: 43 201 точка, шаг 2 секунды.

`npm run dev` запускает приложение, `npm run build` проверяет TypeScript и собирает
production-версию, `npm test` запускает проверки данных и жизненного цикла.

Для подключения метрик передайте в `App` реализацию `CpuDataSource` из
`src/cpu-data.ts`. `loadHistory(signal)` загружает историю, `subscribe(onSamples,
onError)` передаёт новые пакеты и возвращает функцию отписки. Временные метки — Unix
миллисекунды, значения CPU — числа от 0 до 100. Пакеты должны приходить по времени;
повтор последней метки обновляет её значение. Источник должен поддерживать отмену
загрузки через `AbortSignal` и сообщать об ошибках подписки через `onError`.

Хранение ограничено последними сутками и 100 000 точек. Если источник отдаёт более
100 000 измерений за сутки, увеличьте ёмкость `CpuBuffer` или агрегируйте данные в
адаптере. Входящие пакеты объединяются для обновления интерфейса не чаще четырёх
раз в секунду. P95 вычисляется по гистограмме с точностью 0,1 процентного пункта.
Пауза останавливает обновление экрана; сбор данных продолжается. При возобновлении
сразу отображается актуальный буфер.

График следует теме внешнего `ThemeProvider`. На демонстрационной странице есть
переключатель темы; начальная тема берётся из системных настроек. Наблюдение за
контейнером, отложенный resize, подписка и таймеры освобождаются при размонтировании.

Автотесты проверяют ограничение и порядок буфера, окно суток, статистику,
объединение пакетов, паузу и возобновление, отмену загрузки, повтор подключения,
сохранение масштаба и очистку ресурсов графика. Они используют подмену Canvas-движка
и не заменяют проверку отрисовки в браузере.

Ручная проверка интерфейса: светлая и тёмная темы; ширины 375 и 1400 px без
горизонтального переполнения; подсказка при наведении; выделение и сброс масштаба;
состояния загрузки, отсутствия данных и ошибки источника; экспорт CSV.
