# Мониторинг CPU

`npm install`, затем `npm run dev`. Проверки: `npm test` и `npm run build`.

Страница показывает **демонстрационные** данные: около 43 200 измерений за сутки,
новая точка каждые две секунды. Реального API в проекте нет.

Для подключения метрик передавайте в `CpuChart` свойство `data: CpuData`:
`timeline` — отсортированные по возрастанию Unix timestamps в миллисекундах,
`values` — соответствующие значения CPU от 0 до 100 или `null` для пропусков.
Массивы должны быть одинаковой длины. При обновлении передавайте новый объект;
не изменяйте переданные массивы. Получение данных и подписка на сервер остаются
на стороне вызывающего компонента. Сам график отображает только последние 24 часа.

Canvas-график построен на Yagr. Снимки данных и изменения размеров объединяются
в один `requestAnimationFrame`; до кадра сохраняется только последний снимок.
Маркеры каждой точки отключены, наведение показывает точное значение. Тема
берётся из Gravity UI. Обновление серии и темы сохраняет экземпляр графика.
Выделение мышью фиксирует выбранный диапазон; кнопки периода и двойной щелчок
возвращают слежение за новыми данными.

В Yagr 5.3.1 перегрузка `setSeries(timeline, series, {incremental: false})`
пересоздаёт uPlot. Поэтому адаптер заменяет публичный `config.timeline`, затем
вызывает `setSeries('cpu', {data})` внутри пакета обновлений uPlot. При обновлении
версии Yagr следует проверить этот путь в браузере, включая переходы пусто → данные.
Собственный `ResizeObserver` позволяет явно отменять отложенные операции;
при размонтировании отменяется кадр, отключается observer, удаляется обработчик
двойного щелчка и вызывается `dispose()`. Таймер демопотока также очищается.
