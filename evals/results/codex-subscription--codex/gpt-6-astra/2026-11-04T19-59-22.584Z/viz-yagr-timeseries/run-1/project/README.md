# Мониторинг CPU

`npm install`, затем `npm run dev`. Проверки: `npm test` и `npm run build`.

Страница показывает **демонстрационные**, а не реальные системные метрики:
43 201 измерение за последние 24 часа с шагом 2 секунды. Демо явно обозначено
в интерфейсе. API мониторинга в исходном проекте отсутствует.

## Подключение метрик

Передайте в `CpuChart` стабильный объект `CpuSource` вместо
`createDemoCpuSource()` в `App.tsx`:

- `getSnapshot()` возвращает новые массивы `timeline` и `values` одинаковой
  длины. Время — Unix milliseconds в строго возрастающем порядке, значения —
  проценты от 0 до 100. Пустые массивы означают отсутствие данных.
- `subscribe(notify)` вызывает `notify()` при поступлении данных и возвращает
  функцию отписки. Адаптер должен освобождать таймеры, WebSocket и обработчики,
  когда подписчиков больше нет.
- Адаптер хранит только последние сутки. Для равномерных измерений можно
  использовать `CpuBuffer`, задав ёмкость под частоту источника. По умолчанию
  ёмкость рассчитана на шаг 2 секунды; при более частых измерениях её нужно
  увеличить. Буфер отбрасывает неверные и неупорядоченные измерения.

## Отрисовка и жизненный цикл

График использует Canvas через Yagr/uPlot. Массивы точек находятся вне React
state. Уведомления источника объединяются через `requestAnimationFrame`:
за кадр берётся только один актуальный снимок. Существующая серия обновляется
по ID без пересоздания графика; маркеры всех точек отключены. Выбранный
масштаб сохраняется при обновлении, кнопка возвращает к скользящему окну суток.

`ResizeObserver` отслеживает сам контейнер. Смена темы Gravity UI вызывает
`setTheme` на существующем экземпляре. В приложении включена системная тема.
При размонтировании выполняются отписка от источника, отключение observer,
отмена ожидающего animation frame и `dispose()` графика. Это также работает
при повторном монтировании эффектов в React StrictMode.
