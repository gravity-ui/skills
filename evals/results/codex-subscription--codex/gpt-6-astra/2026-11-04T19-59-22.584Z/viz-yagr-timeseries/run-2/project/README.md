# Мониторинг CPU

```sh
npm install
npm run dev
npm run build
npx vitest run
```

`src/CpuChart.tsx` отображает скользящее окно за последние 24 часа. Yagr/uPlot рисует
линию на Canvas без отдельных DOM-элементов для каждой точки. Поступающие пакеты
объединяются в одну отрисовку через `requestAnimationFrame`; данные и тема обновляются
на существующем экземпляре. Выбранный масштаб сохраняется при обновлении данных.
`ResizeObserver` отслеживает контейнер. При размонтировании удаляются подписка,
таймер, observer, ожидающий кадр и экземпляр графика, включая tooltip.

Тема берётся из Gravity UI `ThemeProvider`; приложение по умолчанию следует системной
теме. Наведение показывает время и процент CPU, выделение мышью увеличивает интервал.
Кнопка «Сбросить масштаб» или двойной щелчок возвращают последние сутки.

## Подключение метрик

В репозитории нет API метрик. Страница явно помечена как демонстрационная:
`demoCpuSource` генерирует около 43 200 точек и новое измерение каждые 2 секунды.

Передайте в `CpuChart` стабильный объект `CpuDataSource` из `src/cpuData.ts`:

- `getHistory()` возвращает загруженную историю;
- `subscribe(receive)` передаёт новые пакеты и возвращает функцию отписки;
- `timestamp` — Unix-время в **миллисекундах**, `value` — число от 0 до 100 или
  `null` для разрыва линии при отсутствии измерения;
- история и поток должны идти по возрастанию времени. Повтор последней временной
  метки заменяет значение; запоздавшие, будущие и некорректные точки игнорируются.

Асинхронную загрузку истории можно выполнить до монтирования компонента либо
передать историю первым пакетом подписки. Адаптер должен согласовать историю и
поток без пропусков, а функция отписки — закрывать соединение и отменять запросы.
При изменении объекта `source` компонент переподключается к новому источнику.
Данные старше суток удаляются, даже если новых измерений нет. При высокой частоте
измерений серверу следует ограничивать объём истории согласованной детализацией.
